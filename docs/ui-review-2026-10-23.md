# White Nights UI review — 23 October 2026

## Scope and evidence

Requested review using `ui-ux-pro-max`, with two supplied narrative-game screenshots as visual references. Reviewed the current committed reading/home styles and latest saved desktop/mobile screenshots. This is a design audit, not a new live browser test or a complete accessibility certification. No application code or generated assets changed during this review.

The skill's design-system searches suggested several unsuitable marketing/retro-futurist patterns. These were rejected. Relevant findings retained: readable line length, stable visual hierarchy, keyboard focus, sufficiently large touch targets and reduced-motion support. The existing implementation remains vanilla HTML/CSS/JavaScript with Three.js; no framework migration is proposed.

## Recommended direction: an illustrated literary stage

Keep the lavender city and English-only narrative. Borrow the references' relationship between scene, portrait, nameplate and dialogue. Use cream lettering, muted violet ink and restrained brass accents. A thin irregular frame and occasional railing-inspired corner detail can connect the reader to the canal. Do not copy the references' characters, red battle-like slashes or elaborate gold ornament.

## Reference interpretation

- Reference 1: borrow the portrait extending into the scene, attached nameplate and strong foreground/background separation. Its choices do not imply that this fixed-ending adaptation needs dialogue branches.
- Reference 2: borrow the coherent illustrated frame and clear reading order. Reduce the heavy decoration to a thin line and small recurring motif appropriate to White Nights.
- Preserve the existing homepage composition. Unify its buttons, chapter indicators and the reader's nameplate with the same ink/cream/brass palette; no further homepage rebuild is needed for this pass.

## Asset plan, only after the reading composition is selected

The classroom Qwen API is authorized by the user. No request was made during this audit.

1. Two matching waist-up character images: the Dreamer facing inward from the left, Nastenka from the right. Keep the existing faces, costumes, palette and linework. Request a clean separable background; inspect and prepare alpha cutouts before integration rather than assuming the service returns usable transparency.
2. A first-night meeting scene: railing in the foreground, a clear central reading area, two small figures separated in space.
3. A fourth-night farewell scene: a receding pair and the solitary dreamer, using the same canal architecture and a wider camera view.

Keep expressions neutral for the first layout prototype. Add expressions only after evaluating whether they improve a specific story beat. Do not regenerate all four existing backgrounds. All text, nameplates, buttons and frames remain HTML/CSS/SVG, not text baked into generated images. Keep prompts and generation credits with the assets.

## Suggested implementation order

1. Prototype one Dreamer exchange, one Nastenka exchange and one narration paragraph using existing art; verify hierarchy and panel size first.
2. Add the two character cutouts and selected scene illustrations; check identity/style continuity.
3. Verify desktop 1440px, tablet 768/1024px and phone 375/390px, plus short landscape, long text, keyboard, reduced motion, missing images and stored progress.

## Standards consulted

- WCAG 2.2 normal text contrast minimum: 4.5:1, subject to its stated exceptions. Actual final composited backgrounds must be measured: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html
- WCAG 2.2 AA target size minimum: 24 × 24 CSS pixels, with spacing and other exceptions; larger targets are preferable for primary touch controls: https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html
