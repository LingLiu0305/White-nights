# 《白夜》交互叙事网页：设计稿

日期：2026-10-21  
用途：Assignment 3 的项目设计与后续实现依据。此文件是设计稿，当前尚未创建可运行网页。

## 1. 创作目标与已经确定的方向

面向希望通过网页体验《白夜》故事的读者。读者可以不熟悉原著；必要的人物和情境信息在章节中交代。

作品以每一夜的对话为主体，忠于原著的事件与结局，第四夜是重点场景。阅读、空间感和情绪是主要体验，剧情分支与改变结局不作为目标。

已经由用户确定：

1. 使用 VS Code 作为本地开发中心，最终提供可运行源码和公开 GitHub 仓库。
2. 采用可点击的真实 3D 地图，地点能展示介绍。
3. 每一夜开始时，通过主角标记的移动交代故事位置。
4. 地图的空间组织参考用户提供的图一，美术参考图二的 cel shading、描边与插画质感。
5. 到达章节地点后，从地图过渡到二维夜景、人物剪影与文字，进行线性叙事。

本稿提出的实现建议包括限制地图视角、地图与阅读模式的操作区分，以及先验证一个完整章节流程。这些属于可调整的设计建议。

## 2. 体验流程

主流程：

打开网页 → 地图与操作引导 → 开始第一夜 → 标记沿示意路线移动 → 到达目的地 → 过渡到二维场景 → 阅读对白与独白 → 返回地图 → 开始下一夜。

| 状态 | 玩家操作 | 程序回应与可见反馈 |
| --- | --- | --- |
| 地图浏览 | 点击地点或对应的文字地点按钮 | 地点高亮，打开带标题的介绍面板；关闭面板后恢复地图浏览 |
| 地点介绍 | 阅读、关闭，或点击当前章节的明确入口 | 普通介绍不改变章节进度；章节入口开始本夜过场 |
| 章节移动 | 观看或点击“跳过过场” | 主角标记移动，镜头跟随；跳过时直接设置正确的终点位置 |
| 二维阅读 | 点击继续、按空格、打开阅读记录 | 推进文字或显示记录；地图保持暂停，阅读操作不会点到背后的地图 |
| 章节结束 | 返回地图、继续下一夜，或重读已完成章节 | 更新章节状态和人物位置；重读与继续主线使用不同入口 |

“地点介绍”和“开始故事”在按钮名称与外观上区分。地图探索是可选内容；主线入口始终可找到。介绍不提前披露尚未读到的关键事件。

章节移动期间只允许一次过渡。重复点击不会启动第二条路线，也不会重复进入对白。

## 3. 地图与叙事空间

地图是一张根据小说地点关系组织的微缩叙事地图，具体地点和行程要对照采用的原文片段核对。它不宣称精确还原历史街区。

初期拟以叙述者住处、河岸会面处、娜斯坚卡家附近，以及连接它们的街巷构成地图。建筑体块、河道、栏杆和路灯用于帮助辨认地点。

章节与地点是独立信息：多个夜晚可以对应同一会面地点。标记移动用于表达有文本依据的行程；未交代细节的路线须作为示意呈现。同一地点可以通过章节天色、照明与人物位置的变化反复出现。

地图建议使用固定斜俯视构图，允许有限旋转和缩放，提供“恢复视角”。地点标签与文字地点按钮使用一致名称。

## 4. 视觉与阅读方式

### 地图

美术由简化建筑造型、分层明暗、细描边与轻纸张纹理共同构成。初期色彩方向为蓝紫天光、浅色墙面、青绿屋顶和少量暖黄窗光。

用户提供的参考图用于讨论构图与风格；当前没有将其作为网页素材的安排。项目素材另外制作或采用允许公开分享的来源，并记录出处。

### 地图到二维场景

主角抵达 → 地图镜头靠近 → 画面淡出或交叉淡化 → 二维夜景出现 → 章节文字开始。

二维画面独立构图，避免强行把地图镜头放大成最终插画。两者共享地点特征与色彩，以保持连续性。返回地图时恢复对应章节的标记位置与可用入口。

### 二维阅读

1. 环境背景、人物剪影和文字使用独立图层，便于改变人物距离、姿态和构图。
2. 对白标明说话者；内心独白与环境描写具有明确且可读的样式区别。
3. 文字逐字出现时，第一次继续操作只补全当前段，下一次才进入下一段。
4. 重要停顿由玩家主动继续结束；字体、对比度和每屏文字量以阅读舒适为准。
5. 阅读记录、地图返回入口和章节进度均可辨认；音量控制在加入声音时同时提供。

第四夜重点表现谈话、人物注意力转移、人物离开与最后的空景。具体镜头逐段对应剧本设计，不增加改变原著结局的选择。

四夜是主线结构。“清晨”可以作为正式版本的收束章节；是否纳入及具体篇幅在剧本选段时另行决定，不影响第一轮原型。

## 5. 技术职责与内容组织

建议使用 HTML/CSS/JavaScript 与 Three.js，在本地开发服务器中运行。地图由 Three.js 绘制；按钮、介绍、阅读文字和记录使用普通网页元素，以保证清晰度和可操作性。

| 部分 | 负责内容 |
| --- | --- |
| 地图 | 建筑、地点拾取、标记、受限视角和移动动画 |
| 章节流程 | 当前章节、过场状态、阅读位置和状态切换 |
| 阅读界面 | 二维背景、剪影、文字、继续操作与阅读记录 |
| 地点数据 | 标识、名称、介绍、坐标与可关联的章节 |
| 故事数据 | 章节标识、起终点、场景、文字段落、说话者和视觉提示 |

章节不能依赖固定的独占地点；地点与章节通过标识关联。故事内容与显示逻辑分开保存，便于后续修改文本和审校。

建议在本机保存已完成章节与当前段落。保存不可用时，当前会话仍可继续，界面说明进度未保存。重新开始会先确认，并清理保存的进度。

正式文本需注明原著、使用的译本及自写改编部分；试读文字如属自行改写，应明确标注。AI 辅助选题、设计、编码或素材制作的用途如实写入 PROCESS.md。

## 6. 第一轮原型与验证

第一轮目标是验证完整的一次体验，而非立即完成全部美术与正文：

1. 一张由简化体块构成的地图，至少三个可点击的地点，并有文字地点入口。
2. 一段主角标记移动，以及可跳过且不会重复触发的过场。
3. 一次地图到二维场景的过渡。
4. 一段明确标注来源或改编性质的第一夜连续试读，包含对白、独白和记录。
5. 试读结束后返回地图，正确显示章节完成状态。

正常流程验收：地点点击能显示对应介绍；开始章节后标记抵达正确位置；进入阅读后地图不响应；继续与回看正常；结束后地图状态一致。

恢复流程验收：快速重复点击不会重复启动；跳过过场与正常播放到达相同终点；背景或剪影加载失败时仍可阅读文字。3D 初始化失败时显示平面地点入口与说明，玩家仍可进入试读。

真人试用重点观察：是否分得清介绍与故事入口、能否理解主角移动、过渡后是否知道如何继续，以及文字是否易读。记录实际观察与相应设计决定，不预写用户反馈。
